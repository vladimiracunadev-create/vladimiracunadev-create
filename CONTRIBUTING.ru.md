Спасибо, что рассматриваете возможность внести вклад в эту экосистему. Поскольку она построена вокруг **наблюдаемости**, **воспроизводимости**, **local-first качества** и **идемпотентности**, мы предъявляем высокие требования к целостности кода, чтобы это портфолио оставалось отражением современной инженерии.

## Вклад, которому мы рады

- 🐛 **Исправление ошибок:** Устраняйте выявленные проблемы, желательно с автоматическим тестом (`pytest` и т. п.), подтверждающим исправление.
- 🚀 **Новые возможности:** Архитектурные улучшения и новые интеграции, например с n8n, Ollama или LangGraph.
- 📖 **Документация:** Более понятные объяснения, переводы или явные архитектурные диаграммы (Mermaid или draw.io).
- 🏗️ **Инфраструктура:** Улучшения DevOps-процессов (Kubernetes, CI/CD, Makefile и конфигурация PWA).

## Рабочий процесс (Git Flow)

Проект использует стандартизированный процесс с ветками функциональности:

1. **Сделайте форк** репозитория в свой аккаунт.
2. **Создайте ветку** для вашей функции или исправления от актуальной ветки `main`:

   ```bash
   git checkout -b feature/new-aws-magic
   # or for fixes
   git checkout -b fix/auth-bypass
   ```

3. **Разработайте** изменение.
   - Следуйте устоявшемуся подходу репозитория. Если он использует `uv` для высокопроизводительных процессов Python, не заменяйте его без обоснования.
   - Запустите существующие в проекте защитные проверки.
4. **Зафиксируйте** изменения (commit). Мы используем **Conventional Commits** (`feat:`, `fix:`, `docs:`, `chore:` и т. д.):

   ```bash
   git commit -m "feat: implement global circuit breaker for failed calls"
   ```

5. **Отправьте** ветку (push):

   ```bash
   git push origin feature/new-aws-magic
   ```

6. **Откройте Pull Request (PR)** в ветку `main` этого репозитория.

## Стандарты кода

- **Разработка через тестирование (необязательно, но рекомендуется):** Укажите команды запуска тестов. Если в репозитории есть GitHub Actions для `mypy` или `bandit`, убедитесь, что изменения проходят локально (`make test`, `make lint` или скрипты экосистемы).
- **Docker-first:** Любая необходимая зависимость должна быть описана и доступна через `docker-compose.yml`, чтобы архитектура запускалась менее чем за 60 секунд или иным образом не создавала лишних трудностей локальной настройки.
- **Документация обязательна:** При крупном изменении обновите README и, когда уместно, добавьте поясняющую диаграмму.
