Le Stack technologique du profil provient de ce qui se trouve dans les dépôts publics de ce compte, pas d'une liste d'intentions. Ce document explique ce qui compte comme preuve, de quel dépôt ou lieu provient chaque domaine et ce qui n'est qu'une déclaration de l'auteur.

## Règles d'inclusion

1. **Uniquement des dépôts publics personnels.** Les dépôts privés et les forks de projets tiers ne comptent pas.
2. **La preuve est dans le dépôt.** Compte ce qui apparaît dans le code, les manifestes et lockfiles, Docker/Compose, les workflows CI/CD, Terraform ou la documentation d'un laboratoire ou d'un cursus. Une simple mention dans le texte d'un cours ne compte pas : Snowflake, BigQuery, Spark ou Airflow n'apparaissent que comme contenu de cours et ne figurent donc pas dans le Stack.
3. **Usage, pas années.** Apparaître dans un dépôt prouve un usage, pas des années d'expérience en production.
4. **Le déclaré est à part.** Ce qui ne peut pas être vérifié depuis des dépôts publics est signalé comme déclaré par l'auteur (ci-dessous).

## Déclaré par l'auteur (non vérifiable dans des dépôts publics)

Ces éléments sont dans le Stack parce que l'auteur les utilise, mais aucun dépôt public ne les démontre à lui seul :

- **Cloudflare** — travail personnel.
- **ChatGPT Plus** (depuis 2023), **Antigravity** et **OpenCode** — outils du flux de développement assisté par l'IA.
- **AWS dans des sites opérationnels liés à GitLab** — ce qui est vérifiable publiquement est le projet [proyectos-aws-gitlab](https://gitlab.com/vladimir.acuna.dev-group/proyectos-aws-gitlab), pas ces sites.

## Comment le vérifier

Chacun peut refaire la vérification avec la CLI GitHub (`gh`) :

```bash
gh repo list vladimiracunadev-create --visibility public --source --limit 200
gh api repos/vladimiracunadev-create/<repo>/languages
gh search code "<tech>" --owner vladimiracunadev-create
```

## Comment il est maintenu

- Les technologies et leur graphique sont générés depuis `scripts/stack_data.json` avec `scripts/stack_graphic.py` ; les chiffres du profil sont calculés par le workflow `stats.yml`.
- Une technologie entre dans le Stack quand elle apparaît dans un dépôt public (code, manifeste, workflow ou laboratoire) et en sort si elle n'apparaît plus dans aucun.

## Limites

- Les statistiques de langages de GitHub comptent les fichiers générés et de données (d'où le poids du HTML) : elles montrent ce qu'un dépôt contient, pas ma maîtrise de chaque langage.
- Les dépôts privés et le travail pour des clients ne font pas partie de ce Stack et ne servent pas de preuve.
