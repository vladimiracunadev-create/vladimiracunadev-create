Der Technologie-Stack des Profils stammt aus dem, was in den öffentlichen Repositories dieses Kontos liegt, nicht aus einer Absichtsliste. Dieses Dokument erklärt, was als Nachweis zählt, aus welchem Repository oder Ort jeder Bereich stammt und was nur eine Aussage des Autors ist.

## Aufnahmeregeln

1. **Nur eigene öffentliche Repositories.** Private Repositories und Forks fremder Projekte zählen nicht.
2. **Der Nachweis liegt im Repository.** Es zählt, was in Code, Manifesten und Lockfiles, Docker/Compose, CI/CD-Workflows, Terraform oder in der Dokumentation eines Labors oder Lehrplans steht. Eine beiläufige Erwähnung im Kurstext zählt nicht: Snowflake, BigQuery, Spark oder Airflow kommen nur als Kursinhalt vor und stehen deshalb nicht im Stack.
3. **Nutzung, keine Jahre.** Das Auftauchen in einem Repository belegt Nutzung, keine Jahre produktiver Erfahrung.
4. **Erklärtes steht getrennt.** Was sich aus öffentlichen Repositories nicht prüfen lässt, ist als vom Autor erklärt markiert (unten).

## Vom Autor erklärt (in öffentlichen Repositories nicht prüfbar)

Diese Punkte stehen im Stack, weil der Autor sie nutzt, aber kein öffentliches Repository belegt sie für sich allein:

- **Cloudflare** — persönliche Arbeit.
- **ChatGPT Plus** (seit 2023), **Antigravity** und **OpenCode** — Werkzeuge des KI-gestützten Entwicklungsflusses.
- **AWS in operativen Websites mit GitLab-Bezug** — öffentlich prüfbar ist das Projekt [proyectos-aws-gitlab](https://gitlab.com/vladimir.acuna.dev-group/proyectos-aws-gitlab), nicht diese Websites.

## So lässt es sich prüfen

Jede Person kann die Prüfung mit der GitHub-CLI (`gh`) wiederholen:

```bash
gh repo list vladimiracunadev-create --visibility public --source --limit 200
gh api repos/vladimiracunadev-create/<repo>/languages
gh search code "<tech>" --owner vladimiracunadev-create
```

## Wie er gepflegt wird

- Die Technologien und ihre Grafik werden aus `scripts/stack_data.json` mit `scripts/stack_graphic.py` erzeugt; die Zahlen des Profils berechnet der Workflow `stats.yml`.
- Eine Technologie kommt in den Stack, wenn sie in einem öffentlichen Repository vorkommt (Code, Manifest, Workflow oder Labor), und fällt heraus, wenn sie in keinem mehr vorkommt.

## Grenzen

- Die Sprachstatistiken von GitHub zählen generierte und Datendateien (deshalb wiegt HTML so viel): Sie zeigen, was ein Repository enthält, nicht wie gut ich jede Sprache kann.
- Private Repositories und Kundenarbeit gehören nicht zu diesem Stack und dienen nicht als Nachweis.
