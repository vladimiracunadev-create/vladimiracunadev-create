The profile's Technology Stack comes from what is in this account's public repositories, not from a list of intentions. This document explains what counts as evidence, which repository or place each area comes from, and what is only the author's statement.

## Inclusion rules

1. **Own public repositories only.** Private repositories and forks of third-party projects do not count.
2. **Evidence lives in the repository.** What counts is what appears in code, manifests and lockfiles, Docker/Compose, CI/CD workflows, Terraform, or in the documentation of a lab or curriculum. A passing mention in course text does not count: Snowflake, BigQuery, Spark or Airflow appear only as course content, so they are not in the Stack.
3. **Use, not years.** Appearing in a repository is evidence of use, not a claim of years of productive experience.
4. **What is declared is kept apart.** Whatever cannot be checked from public repositories is marked as declared by the author (below).

## How to check it

Anyone can repeat the check with the GitHub CLI (`gh`):

```bash
gh repo list vladimiracunadev-create --visibility public --source --limit 200
gh api repos/vladimiracunadev-create/<repo>/languages
gh search code "<tech>" --owner vladimiracunadev-create
```

## How it is maintained

- The technologies and their graphic are generated from `scripts/stack_data.json` with `scripts/stack_graphic.py`; the profile's figures are computed by the `stats.yml` workflow.
- A technology enters the Stack when it appears in a public repository (code, manifest, workflow or lab) and leaves if it stops appearing in any.

## Limits

- GitHub language statistics count generated and data files (which is why HTML weighs so much): they show what a repository contains, not how well I know each language.
- Private repositories and client work are not part of this Stack and are not used as evidence.
