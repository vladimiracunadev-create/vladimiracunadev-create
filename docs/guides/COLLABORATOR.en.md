# 🤝 Guide for collaboration, open source and security

[← Start here](../START_HERE.en.md) · [Español](COLLABORATOR.md) · **English**

## In one line

The repositories are meant to be cloned, run and validated; contributions, reports and fixes are welcome.

## What do you want to do?

| I want to… | What to do |
|---|---|
| **Contribute code or documentation** | Read [CONTRIBUTING](../../CONTRIBUTING.en.md) and open an issue or PR in the relevant repo |
| **Report a vulnerability** | Follow [SECURITY](../../SECURITY.en.md); do not publish details in an open issue |
| **Fix a translation** | This profile and its documents are in 22 languages and some translations can be improved; corrections are especially useful |
| **Understand the community rules** | [Code of conduct](../../CODE_OF_CONDUCT.en.md) |
| **Use or reuse a repository** | Each repo declares its license and limits; check them before reusing it |

## How these repos are run

- Standardized tooling: `Makefile`, `doctor` and `smoke` per repo.
- Security as a pipeline: secret scanning, static analysis and SBOM per release.
- Forbidden practices stated explicitly.
- Documentation by audience: whoever operates, develops or audits finds their part.

## What is not my own work

The account keeps [52 forks of third-party projects](../ECOSYSTEM.en.md#forks). They are not my own work: to contribute to them, do it in the original project (the "Original project" column links to each one).
