## In una riga

I repository sono pensati per essere clonati, eseguiti e validati; contributi, segnalazioni e correzioni sono benvenuti.

## Cosa vuoi fare?

| Voglio… | Cosa fare |
|---|---|
| **Contribuire con codice o documentazione** | Leggi [Contribuire](../../CONTRIBUTING.it.md) e apri una issue o una PR nel repository interessato |
| **Segnalare una vulnerabilità** | Segui [Sicurezza](../../SECURITY.it.md); non pubblicare dettagli in una issue aperta |
| **Correggere una traduzione** | Questo profilo e i suoi documenti sono in 22 lingue e alcune traduzioni sono migliorabili; le correzioni sono particolarmente utili |
| **Capire le regole di convivenza** | [Codice di condotta](../../CODE_OF_CONDUCT.it.md) |
| **Usare o riutilizzare un repository** | Ogni repository dichiara licenza e limiti; verificali prima di riutilizzarlo |

## Come si lavora in questi repository

- Tooling standardizzato: `Makefile`, `doctor` e `smoke` per repository.
- Sicurezza come pipeline: scansione dei segreti, analisi statica e SBOM per release.
- Pratiche vietate dichiarate esplicitamente.
- Documentazione per pubblico: chi gestisce, sviluppa o verifica trova la sua parte.

## Cosa non è opera propria

L'account conserva [52 forks](../ECOSYSTEM.it.md#forks) di progetti di terzi. Non sono opera propria: per contribuire, fallo nel progetto originale (la colonna «Progetto originale» rimanda a ciascuno).
