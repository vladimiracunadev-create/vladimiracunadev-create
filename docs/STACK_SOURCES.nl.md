De Technologiestack van het profiel komt uit wat er in de openbare repositories van dit account staat, niet uit een lijst met voornemens. Dit document legt uit wat als bewijs telt, uit welke repository of plek elk gebied komt en wat slechts een verklaring van de auteur is.

## Opnameregels

1. **Alleen eigen openbare repositories.** Privérepositories en forks van projecten van derden tellen niet mee.
2. **Het bewijs zit in de repository.** Wat telt, staat in code, manifesten en lockfiles, Docker/Compose, CI/CD-workflows, Terraform of in de documentatie van een lab of curriculum. Een losse vermelding in cursustekst telt niet: Snowflake, BigQuery, Spark of Airflow komen alleen als cursusinhoud voor en staan daarom niet in de stack.
3. **Gebruik, geen jaren.** Voorkomen in een repository is bewijs van gebruik, geen claim van jaren productieve ervaring.
4. **Wat verklaard is, staat apart.** Wat niet uit openbare repositories te controleren is, is gemarkeerd als verklaard door de auteur (hieronder).

## Verklaard door de auteur (niet verifieerbaar in openbare repositories)

Deze onderdelen staan in de stack omdat de auteur ze gebruikt, maar geen openbare repository bewijst ze op zichzelf:

- **Cloudflare** — persoonlijk werk.
- **ChatGPT Plus** (sinds 2023), **Antigravity** en **OpenCode** — tools van de AI-ondersteunde ontwikkelflow.
- **AWS in operationele websites gekoppeld aan GitLab** — openbaar verifieerbaar is het project [proyectos-aws-gitlab](https://gitlab.com/vladimir.acuna.dev-group/proyectos-aws-gitlab), niet die websites.

## Hoe te controleren

Iedereen kan de controle herhalen met de GitHub-CLI (`gh`):

```bash
gh repo list vladimiracunadev-create --visibility public --source --limit 200
gh api repos/vladimiracunadev-create/<repo>/languages
gh search code "<tech>" --owner vladimiracunadev-create
```

## Hoe het wordt bijgehouden

- De technologieën en hun grafiek worden gegenereerd uit `scripts/stack_data.json` met `scripts/stack_graphic.py`; de cijfers van het profiel berekent de workflow `stats.yml`.
- Een technologie komt in de stack wanneer ze in een openbare repository voorkomt (code, manifest, workflow of lab) en verdwijnt als ze in geen enkele meer voorkomt.

## Grenzen

- GitHub-taalstatistieken tellen gegenereerde bestanden en databestanden mee (daarom weegt HTML zo zwaar): ze tonen wat een repository bevat, niet hoe goed ik elke taal ken.
- Privérepositories en werk voor klanten maken geen deel uit van deze stack en dienen niet als bewijs.
