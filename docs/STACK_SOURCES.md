El Stack tecnológico del perfil sale de lo que hay en los repositorios públicos de esta cuenta, no de una lista de intenciones. Este documento explica qué cuenta como evidencia, de qué repositorio o lugar sale cada área y qué es solo una declaración del autor.

## Reglas de inclusión

1. **Solo repositorios públicos propios.** No cuentan los repositorios privados ni los forks de proyectos de terceros.
2. **La evidencia está en el repositorio.** Cuenta lo que aparece en código, manifiestos y lockfiles, Docker/Compose, workflows de CI/CD, Terraform o en la documentación de un laboratorio o currículo. Una mención suelta en el texto de un curso no cuenta: Snowflake, BigQuery, Spark o Airflow aparecen solo como contenido de cursos y por eso no figuran en el Stack.
3. **Uso, no años.** Aparecer en un repositorio es evidencia de uso, no una afirmación de años de experiencia productiva.
4. **Lo declarado va aparte.** Lo que no se puede comprobar desde repositorios públicos se marca como declarado por el autor (más abajo).

## Declarado por el autor (no verificable en repositorios públicos)

Estas piezas están en el Stack porque el autor las usa, pero ningún repositorio público las demuestra por sí solo:

- **Cloudflare** — trabajo personal.
- **ChatGPT Plus** (desde 2023), **Antigravity** y **OpenCode** — herramientas del flujo de desarrollo asistido por IA.
- **AWS en webs operativas asociadas a GitLab** — lo verificable en público es el proyecto [proyectos-aws-gitlab](https://gitlab.com/vladimir.acuna.dev-group/proyectos-aws-gitlab), no esas webs.

## Cómo comprobarlo

Cualquiera puede repetir la verificación con la CLI de GitHub (`gh`):

```bash
gh repo list vladimiracunadev-create --visibility public --source --limit 200
gh api repos/vladimiracunadev-create/<repo>/languages
gh search code "<tech>" --owner vladimiracunadev-create
```

## Cómo se mantiene

- Las tecnologías y su gráfico se generan desde `scripts/stack_data.json` con `scripts/stack_graphic.py`; las cifras del perfil las calcula el workflow `stats.yml`.
- Una tecnología entra al Stack cuando aparece en un repositorio público (código, manifiesto, workflow o laboratorio) y sale si deja de aparecer en alguno.

## Límites

- Las estadísticas de lenguajes de GitHub cuentan archivos generados y de datos (por eso HTML pesa tanto): sirven para saber qué hay en un repositorio, no cuánto sé de cada lenguaje.
- Los repositorios privados y el trabajo para clientes no forman parte de este Stack ni se usan como evidencia.
