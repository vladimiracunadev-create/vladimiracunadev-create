Sicherheit, Nachvollziehbarkeit und Observability sind Grundpfeiler dieses Projekt-Ökosystems. Wir nehmen jede Meldung zur Integrität unserer Anwendungen ernst.

## Unterstützte Versionen

Derzeit erhalten nur `main` – die jeweils neueste Iteration beziehungsweise das neueste Release-Tag – in allen Repositories direkte Updates und Sicherheitspatches. Ältere Versionen unter nicht unterstützten Tags sind nicht abgedeckt, sofern die Hinweise des Repositorys nichts anderes ausdrücklich festlegen.

## Eine Schwachstelle melden

**Bitte melden Sie Sicherheitsprobleme nicht über öffentliche GitHub Issues.** Dadurch würde die Schwachstelle böswilligen Akteuren bekannt, bevor ein Patch veröffentlicht werden kann.

Für Sicherheitsmeldungen, kritische Integritätsfehler oder behebbare unsichere Standardeinstellungen – etwa offengelegte Zugangsdaten, Remote Code Execution, schwere Code-Injection oder Authentifizierungsumgehung – gehen Sie wie folgt vor:

1. **Senden Sie eine E-Mail** direkt an `vladimir.acuna.dev@gmail.com`.
2. Geben Sie an:
   - Das betroffene Ökosystem oder Repository, zum Beispiel `mcp-ollama-local` oder `social-bot-scheduler`.
   - Detaillierte Schritte zur Reproduktion der Schwachstelle.
   - Optional einen Proof of Concept (PoC) als Skript oder Video, sofern zutreffend.
   - Die mögliche Sicherheitsauswirkung, bewertet nach einschlägigen technischen Standards.

Ich melde mich so schnell wie möglich, in der Regel innerhalb von 48 Geschäftsstunden. Sobald das Problem analysiert und behoben ist, erhalten Sie – falls Sie genannt werden möchten und der Fund überprüfbar ist – eine angemessene öffentliche Anerkennung in unseren Sicherheitsberichten oder im CHANGELOG.

Danke, dass Sie helfen, diese Infrastruktur sicher und professionell zu halten.
