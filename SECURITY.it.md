# Politica di Sicurezza e Divulgazione Responsabile

**Lingue:** [ES](SECURITY.md) · [EN](SECURITY.en.md) · [PT](SECURITY.pt.md) · [IT](SECURITY.it.md) · [FR](SECURITY.fr.md) · [ZH](SECURITY.zh.md)

Sicurezza, tracciabilità e osservabilità sono pilastri di questo ecosistema di progetti. Prendiamo con la massima serietà ogni segnalazione relativa all'integrità delle nostre applicazioni.

## Versioni Supportate

Attualmente, solo `main`—l'ultima iterazione o tag di release—nei diversi repository riceve aggiornamenti diretti e patch di sicurezza. Le versioni precedenti con tag non supportati non sono coperte, salvo esplicita indicazione contraria nelle note del repository.

## Come Segnalare una Vulnerabilità

**Non segnalare problemi di sicurezza tramite Issue GitHub pubbliche.** Ciò esporrebbe la vulnerabilità ad attori malevoli prima che possa essere pubblicata una correzione.

Per segnalazioni di sicurezza, gravi problemi di integrità o impostazioni predefinite insicure ma mitigabili—come credenziali esposte, esecuzione remota di codice, gravi code injection o bypass dell'autenticazione—segui questi passaggi:

1. **Invia un'email** direttamente a `vladimir.acuna.dev@gmail.com`.
2. Includi:
   - L'ecosistema o il repository interessato, ad esempio `mcp-ollama-local` o `social-bot-scheduler`.
   - I passaggi dettagliati per riprodurre la vulnerabilità.
   - Facoltativamente, una proof of concept (PoC) in formato script o video, quando applicabile.
   - Il possibile impatto sulla sicurezza valutato secondo standard tecnici pertinenti.

Ti contatterò il prima possibile, generalmente entro 48 ore lavorative. Dopo l'analisi e la mitigazione del problema, se desideri essere accreditato e la scoperta è verificabile, riceverai il dovuto riconoscimento pubblico nei nostri rapporti di sicurezza o nel CHANGELOG.
